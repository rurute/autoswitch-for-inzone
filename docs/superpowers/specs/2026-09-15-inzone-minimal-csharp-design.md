- 対象: Windows 11 / INZONE Buds / INZONE Hub、作者の日常利用

## 1. 目的と既存資料の扱い

C# の最小トレイアプリで既存の自動切り替えを再現し、作者が日常利用を始められる状態にする。

今回の実装範囲は本書を基準にする。既存の `2026-09-15-autoswitch-for-inzone-design.md` と同名の実装計画は、一般公開版の参考資料として残す。そちらの19タスクを今回の実装手順として実行しない。一般公開版の全機能を将来実装することも、今回の約束には含めない。

PowerShell 版の spec・コード・テストは、既存挙動の移植と比較の基準にする。今回の完了は一般公開や Issue rurute/inzone-auto-switch#1 のクローズを条件にしない。

## 2. 最初の日常利用版に含めるもの

- C# による ActionLog.log の監視と、接続・切断時の既定再生デバイス切り替え
- 設定ファイルからの設定読み込み。変更はアプリ再起動で反映
- 接続中・未接続・不明の3状態を示すトレイアイコンとツールチップ
- トレイメニュー: 設定ファイルを開く、ログフォルダを開く、Windows ログオン時の自動起動 ON/OFF、終了
- 多重起動防止。起動済みなら後から起動したプロセスを終了する
- 診断用のファイルログ

トレイが示すのは検知したヘッドセットの状態であり、音声切り替え成功の保証ではない。切り替え失敗などの詳細はログで確認する。

今回含めないもの:

- 設定画面、設定の動的反映、出力先の自動推奨・ID自動修復
- Windows 通知、問題別のアイコン、テーマ変更への追従、多言語化
- 二重起動時のウィンドウ表示連携、名前付きパイプ
- 一時停止、手動切り替えメニュー、録音デバイスの切り替え
- 複数ヘッドセット・プロファイル、HID直接監視
- インストーラ、リリース自動化、一般公開、リポジトリ改名・履歴書き換え
- 独自アイコン生成ツール

## 3. 維持する動作

PowerShell 版の実装とテストを基準に、以下を維持する。

- 状態遷移時のみ切り替え、次の遷移までユーザーの手動変更を尊重する
- logId の重複排除、途中行の持ち越し、BOM・UTF-8、ログの truncate・再生成への対応
- 既存版と同じ条件での起動時同期。古いイベントで不用意に切り替えない
- Hub 未起動・ログ未存在での待機と、その後の監視再開。Hub 自体は起動しない
- 読み取り失敗時のバックオフと復帰。想定外の監視処理例外をログへ残す
- 切り替え先不在・音声操作失敗でも監視を継続し、同じ状態で切り替えを繰り返さない
- ログレベル、サイズ上限によるローテーション、同一メッセージの連続出力抑制
- 管理者権限を要求しない

音声操作が既存版と同じ範囲の既定出力を変更することは、段階1の実機確認で比較する。録音デバイスは変更しない。

## 4. 最小構成（今回の具体案）

既存の C# 設計で選定済みの .NET 10 を引き継ぐ。設定画面がない今回のトレイには標準の WinForms NotifyIcon を使用する案とし、WPF-UI・MVVM・通知用ライブラリは導入しない。

責務を以下の3つに分ける。将来の機能のための抽象化は追加しない。

| 構成 | 責務 |
|---|---|
| Core | ログ読み取り・パース・状態遷移・監視処理・設定読み込み・診断ログ。UIと実機音声操作に依存しない |
| Audio | Windowsの再生デバイス列挙、既定出力の取得と変更 |
| App | 実行ループ、トレイ、単一起動、開始・終了、自動起動登録 |

App がバックグラウンドで監視処理を駆動し、状態変更を UI スレッドへ渡す。設定は起動時に確定し、実行中の設定更新や保存競合を扱わない。終了時には監視を停止し、音声操作のリソース・アイコン・Mutex を解放する。

段階1・2の手動確認には開発用のコンソール実行口を用意する。最終的なトレイ版ではコンソールを表示しない。

### 設定と保存先

- 既存の config.json のキーと既定値を引き継ぐ。出力先はデバイス名で指定する
- 名前一致の候補が複数ある場合は既存版同様に先頭を使用する
- 設定は `%LOCALAPPDATA%\AutoSwitchForInzone\config.json`、ログは同フォルダ配下の `logs` に保存する
- 初回起動で設定ファイルがなければ既定値のファイルを作る。既存ファイルは上書きしない
- 型・範囲不正などの読み込み時の扱いは既存版に合わせ、警告をログに残す
- PowerShell 版からの設定自動移行は作らず、作者が必要な値を手動で転記する

### 起動

- Mutex は新版専用とする。新版同士の重複起動を防ぐ
- 自動起動は HKCU Run キーで登録し、管理者権限を要求しない
- 自動起動は初期状態で OFF。トレイから明示的に ON/OFF を切り替える
- メニューのチェック状態は Run キーの登録有無に合わせる。登録失敗時は成功した表示にせずログへ残す
- exe は作者が決めた固定フォルダに配置する。移動時は自動起動を OFF にして移動し、移動後に ON にする。移動検知・自動修復は作らない
- UI の起動や継続が不可能なエラーは、可能な範囲でログとエラーダイアログに記録して終了する

## 5. 実装の4段階

各段階の完了を確認してから次へ進む。旧版のファイルとテストは全段階を通じて残す。

| 段階 | 成果物 | 完了条件 |
|---|---|---|
| 1. 音声操作 | C# の音声操作と開発用実行口 | 実機のデバイス一覧を取得でき、指定して Buds・スピーカーへ切り替えられる。既存版の音声操作と比較できる |
| 2. 自動切り替え | ログ監視、状態判定、設定、ログ | コンソールで動かし、出し入れで切り替わる。手動変更を尊重し、既存挙動の自動テストが通る |
| 3. トレイ常駐 | 状態表示、設定・ログを開く、終了、単一起動 | コンソールなしで動き、状態表示が変わり、メニューから各操作ができる |
| 4. 日常利用へ移行 | 自動起動と運用確認 | 自動起動の ON/OFF、ログオン、スリープ復帰を確認し、旧版を停止して新版を日常利用できる |

## 6. 検証と旧版の扱い

- Core は C# の自動テストで検証する。旧版のテスト観点を引き継ぎ、テスト件数自体は目標にしない
- 音声操作、トレイ、起動・終了、自動起動は各段階で Windows 実機確認を行う
- 旧版のコードとテストを削除しない。新版の配置は旧版のソースと分離する
- 旧版と新版を同時に監視させない。実機確認前に旧版を停止する。新版専用 Mutex では旧版との同時起動は防げないため、切り替え手順に明記する
- 移行時は旧版の自動起動を無効化し、新版の自動起動を有効化する
- 問題があれば新版を終了し自動起動を無効化して、旧版の起動を復元できる状態を保つ
- 旧版の削除、一般公開、Issue rurute/inzone-auto-switch#1 のクローズは今回実施しない
