# 設定画面と再起動なしの反映 — 設計仕様

- 日付: 2026-09-17
- ステータス: 承認済み・実装済み（2026-09-17。Codex レビュー2回、2回目でブロッキング指摘なし。実機確認は [手動確認記録](../../manual-test-settings-window.md)）
- 実装計画: `../plans/2026-09-17-settings-window.md`（本書の承認後に作成）
- 関連: Issue rurute/inzone-auto-switch#9（本書の対象）、Issue rurute/inzone-auto-switch#8（録音の切り替え。完了済み）、Issue rurute/inzone-auto-switch#14（「既に既定」の判定。本書では扱わない）、Issue rurute/inzone-auto-switch#1
- 前提: 最小 C# トレイ版（`2026-09-15-inzone-minimal-csharp-design.md`）の段階1〜4 と録音の切り替え（`2026-09-16-capture-device-switching-design.md`）が完了し、作者が日常利用している
- 対象: Windows 11 / INZONE Buds / INZONE Hub、作者の日常利用

## 1. 目的

`config.json` を手で編集しなくても、切り替え先を変えられるようにする。

いまは切り替え先をデバイス名で一字一句正確に書く必要があり、変更はアプリを再起動しないと効かない（最小版 spec §2「変更はアプリ再起動で反映」、§4「設定は起動時に確定し、実行中の設定更新や保存競合を扱わない」）。本書では次の2つを加える。

- トレイから開く設定画面で、実在するデバイスの一覧から切り替え先を選ぶ
- 保存したら、アプリを再起動せずに次の接続・切断から新しい設定で切り替える

## 2. 既存 spec との関係

- 最小版 spec §2 が「今回含めないもの」とした「設定画面、設定の動的反映」のうち、**本書 §3 の6項目に限って**加える。
- 最小版 spec §4「設定は起動時に確定し、実行中の設定更新や保存競合を扱わない」は、**6項目については本書で置き換える。**6項目以外（ポーリング間隔、`actionLogPath`、ログの設定、起動時同期の設定）は従来どおり起動時に確定する。
- 最小版 spec §4「既存ファイルは上書きしない」は**起動時の既定ファイルの作成について引き続き維持する。**設定画面での保存は、作者が明示的に行う操作として、既存ファイルの6項目だけを書き換える（§5）。
- 切り替えの規則・ログの文言・終了の契約（最小版 plan §6 と録音 spec §4「取り消しのあとの音声操作は多くとも1回」）は変えない。
- UI の土台は WinForms とする（Issue rurute/inzone-auto-switch#9 の決定。WPF + WPF-UI は採らない）。検証・保存・反映は Core に置き、画面は薄くする。

## 3. 画面で扱う項目

| 画面の項目 | config.json のキー | 選び方 |
|---|---|---|
| 接続時の再生デバイス | `budsDevice` | 再生デバイスの一覧から選ぶ |
| 接続時の録音デバイス | `budsInputDevice` | 録音デバイスの一覧から選ぶ。「（未設定）」も選べる |
| 切断時の再生デバイス | `speakerDevice` | 再生デバイスの一覧から選ぶ |
| 切断時の録音デバイス | `speakerInputDevice` | 録音デバイスの一覧から選ぶ。「（未設定）」も選べる |
| 接続したら切り替える | `switchOnConnect` | チェックボックス |
| 切断したら切り替える | `switchOnDisconnect` | チェックボックス |

これ以外のキーは画面に出さず、従来どおり `config.json` を手で編集して再起動で反映する。トレイメニューの「設定ファイルを開く」は残す。

## 4. 画面の動作

### 開き方

- トレイメニューの先頭に「設定(&S)...」を足す。トレイアイコンのダブルクリックでも開く。
- 設定画面は同時に1つだけ開く。開いているときにもう一度開く操作をしたら、既存の画面を前面に出す。
- 開くたびに `config.json` を読み直し、デバイスの一覧を取り直す。開いている間は自動で読み直さない（ファイルの変更を見張らない）。

### 表示する値

- 各項目の初期値は、開いた時点の `config.json` を既存の `SettingsLoader.Load` で読んだ値とする（不正な値は既存の規則どおり既定値に置き換わった値）。
- 選択肢は、Windows が有効（DEVICE_STATE_ACTIVE）としているデバイスの名前を、流れ（再生・録音）ごとに一覧の順で並べる。同じ名前（大文字小文字を区別しない）が複数あれば1つにまとめる（切り替えは名前で照合し、一致した先頭を使うため、区別しても意味がない）。
- **設定されている名前が一覧に無いとき**（いま接続していない Buds など）は、その名前を「{名前}（未接続）」として選択肢の先頭に足し、選んだ状態にする。何も触らずに保存すれば、その名前がそのまま保存される。
- 録音の2項目には「（未設定）」の選択肢を置く。設定が空なら「（未設定）」を選んだ状態にする。
- 選択肢の並びは、**「{名前}（未接続）」（あるときだけ）→「（未設定）」（録音だけ）→ 一覧のデバイス**の順とする。
- デバイスの一覧を取得できなかった流れは、画面の上部に「{再生/録音}デバイスの一覧を取得できません: {詳細}」を表示し、選択肢は設定されている名前（と録音の「（未設定）」）だけにする。保存はできる。

### 保存とキャンセル

- 「保存」を押すと、§5 の手順でファイルを書き換え、成功したら §6 の手順で動作中の設定に反映し、画面を閉じる。
- 保存に失敗したら、理由をダイアログで出す。画面は閉じず、動作中の設定も変えない。
- **開いた時点で `config.json` が無い・解析できない・ルートがオブジェクトでない場合**は、画面の上部に理由を表示し、「保存」を押せなくする（選択肢は表示する）。既定値のファイルで上書きしない。手で直してから開き直す。
- 「キャンセル」と × は、何も保存せずに画面を閉じる。未保存の変更があっても確認しない。
- 保存しても、**その場ではデバイスを切り替えない。**新しい設定は次の接続・切断（状態遷移）から使う。

### 終了との関係

- 設定画面を開いたままトレイメニューの「終了」を選んだら、保存せずに画面を閉じて従来どおり終了する。
- 設定画面の後片付けは、トレイの後片付け（最小版 段階3 の Release）の中で、監視の停止より前に行う。

## 5. 保存の形式

保存は Core の1か所で行う。入力はファイルのパスと6項目の値、出力は成功か、失敗とその理由。ファイルの読み書きの失敗は例外を外へ出さない（引数の誤り（null・空のパス、null の値）はプログラムの誤りとして例外にする。plan レビュー F5 で明確化、2026-09-17）。

1. **保存の直前に `config.json` を読み直す。**ファイルが無い・JSON として解析できない・ルートがオブジェクトでない場合は、書かずに失敗を返す（開いた後に壊された場合もここで止まる）。
2. **6項目のキーだけを書き換え、ほかは残す。**
   - ルートのプロパティを先頭から順に書き出す。
   - 6項目のキー（大文字小文字を区別しない）に当たるプロパティは、**最初に現れた位置に、正式な表記のキー名（§3 の表）と新しい値で1回だけ書く。**同じキーの2回目以降の出現（大文字小文字違いを含む）は書かない。
   - それ以外のプロパティは、キー名も値もそのまま書く（数値の表記、未知のキー、6項目以外の重複キーを含む）。
   - ファイルに無かった6項目のキーは、最後に §3 の表の順で足す。
   - 録音で「（未設定）」を選んだ項目は空文字 `""` を書く（キーは残す）。
3. **書式は既定ファイル（`SettingsLoader.CreateDefaultFileIfMissing`）にそろえる。**BOM 付き UTF-8、インデントあり、改行は LF、日本語をエスケープしない、末尾に改行1つ。手で入れた空白や改行の位置は保たない（キーの順と値は保つ）。
4. **同じフォルダの一時ファイルに書いてから、`config.json` へ名前を変えて置き換える。**
   - 一時ファイルの名前は `config.json.tmp` とする（残っていたら上書きする）。書き終えたらディスクへ書き出し（flush）、閉じてから置き換える。
   - 置き換えは `File.Move(一時ファイル, config.json, overwrite: true)`（Windows では `MoveFileEx` の上書きの名前変更）で行う。`File.Replace`（`ReplaceFileW`）は、失敗の段階によって元のファイルが元のパスに残らない場合があると公式に記載されているため使わない。名前変更の上書きは、失敗したら `config.json` を変えずに終わり、成功したら新しい内容に替わる。同じフォルダ内の名前変更で内容をコピーしないため、内容の一部だけが書かれた `config.json` は生じない。
   - 一時ファイルへの書き込み・書き出し・置き換えのどこで失敗しても、`config.json` は変わらない（書き込みは一時ファイルにしか行わないため）。失敗したら一時ファイルの削除を試みる。
   - **一時ファイルの削除も失敗したら**、保存の失敗の理由に「一時ファイルが残っています: {パス}」を足して返す。残った一時ファイルは読み込みに使われず、次の保存で上書きされる。
   - 置き換えのあと、元の `config.json` のファイル属性・作成日時・アクセス権が保たれることは保証しない（Windows のファイルシステムトンネリングで作成日時が引き継がれる場合もある。作者の1人利用のフォルダで、`config.json` に特別な属性を付ける運用は無いため許容する）。読み取り専用の `config.json` は名前変更の上書きが失敗するので、保存の失敗になる。
5. 画面を開いていた間に `config.json` が手で編集されていた場合、6項目は画面の値、それ以外は保存時点のファイルの値になる。これを意図した動作とし、衝突の検知や確認はしない。

保存に成功したら、Info で次の1行をログに残す。

```text
設定画面で保存しました: 接続時 再生={名前} 録音={名前} / 切断時 再生={名前} 録音={名前} / switchOnConnect={true|false} switchOnDisconnect={true|false}
```

録音の未設定は `（未設定）` と書く。保存の失敗は Warn で `設定を保存できません: {理由}` を残す。

## 6. 動作中の設定への反映

### 方式

**設定を1か所に置き、保存したらその中身を新しいものへ入れ替える。**監視は止めず、作り直さない。

- Core に、動作中の設定を持つ小さな入れ物を置く。中身は不変の `AppSettings` で、読み出しと入れ替えはスレッドをまたいで安全に行える（参照の入れ替えだけで、ロックを待たない。読み出しと入れ替えは `Volatile.Read` / `Volatile.Write` で行い、監視スレッドが古い参照を読み続けないようにする。入れ替えるのは UI スレッドだけなので、`Interlocked` の比較交換は要らない）。
- `AutoSwitchEngine` は、**切り替え（`SwitchFor`）を始めるときに入れ物から設定を1回だけ取り出し、その1回の切り替え（向きの ON/OFF の判定、再生、録音）をすべてその設定で行う。**1回の切り替えで古い設定と新しい設定が混ざることはない。
- 保存に成功したら、UI スレッドで「いまの中身の6項目だけを保存した値に置き換えたもの」を入れる。6項目以外（ポーリング間隔、`actionLogPath`、ログの設定、起動時同期の設定）は起動時の値のまま変わらない。ファイルの6項目以外が手で変えられていても、動作中の設定には取り込まない。
- エンジンのそれ以外の読み取り（ポーリング間隔、起動時同期の条件など）は起動時の値を使い続ける。

### 採らなかった方式

- **保存したら監視を止めて作り直す**: 作り直すと起動時同期が走り、保存しただけで切り替わる可能性がある（§4「その場では切り替えない」と矛盾）。監視の停止は最大30秒待つ設計（段階3）で、保存のたびにその待ちと停止を確認できない場合の扱いが要る。状態と既読の logId も失う。
- **監視スレッドへ変更を送り、区切りで受け取らせる**: 切り替えについては上の方式と同じ結果で、仕組みだけが増える。

### 守ること

- 監視スレッド・`MonitorRunner`・終了の手順は変えない。反映は監視スレッドに新しい処理を足さないので、終了の契約（取り消しのあとの音声操作は多くとも1回）はそのまま成り立つ。
- 状態（接続中・未接続・不明）と既読の logId は保存の前後で変わらない。
- 切り替えの途中で保存されても、その切り替えは始めたときの設定で最後まで行う。

## 7. 構成

最小版の Core / Audio / App の分担を保つ。Audio は変えない。

### Core（`AutoSwitch.Core`）

- **動作中の設定の入れ物**: 読み出しと入れ替え。`AutoSwitchEngine` がコンストラクタで受け取った `AppSettings` から作って公開し、トレイはエンジンから受け取る。コンストラクタの引数は変えず、既存のテストを壊さない（入れ物を受け取る多重定義を足すと、既存のテストの `new AutoSwitchEngine(null!, ...)` があいまいな呼び出しになるため。plan 作成時に変更、2026-09-17）。
- **開くときの読み込み**: `SettingsLoader.Load` で読んだ6項目に加え、ファイルが無い・解析できない・ルートがオブジェクトでないかを判定して返す（`Load` はこれらの場合も既定値を返すため、保存を押せなくする判定は別に持つ。§4）。
- **画面のモデル**: 画面の見た目に依存しない部分をすべて持つ。
  - 入力: 読み込んだ設定の6項目、流れごとのデバイス名の一覧（または取得の失敗理由）
  - 出力: 4つの選択項目それぞれの選択肢（表示名、保存する値、未接続・未設定の区別）と初期の選択、2つのチェックの初期値
  - 選んだ結果から、保存する6項目の値を作る。再生の2項目が空にならないことを確かめる（選択肢の作り方から通常は空にならないが、Core で保証する）
- **保存**: §5 の手順。ファイルを読む前後・書く前後の失敗をすべて結果に変換する。
- **反映の値の組み立て**: 動作中の `AppSettings` と保存した6項目から、新しい `AppSettings` を作る（6項目以外は元の値）。
- **ログの文言**: §5 の保存ログの1行。

### App（`AutoSwitch.App`）

- **設定画面のフォーム**: WinForms。コントロールの配置、Core のモデルとの受け渡し、ダイアログの表示だけを行う。
- **デバイスの一覧の取得**: 既存の `CoreAudioSession` で、流れごとに一覧を取り、失敗は理由の文字列にしてモデルへ渡す。画面を開くときに UI スレッドで1回だけ行い、取り終えたらセッションを破棄する。セッションは監視スレッドのものと共有しない（監視側は切り替えのたびに自分のスレッドで開いて破棄する）。列挙は同期で行うため、列挙が止まるとその間トレイの操作も止まる。列挙はすぐ返ると見込み（§8 の実機確認「開く」で、開くまでに目立つ待ちが無いことを確かめる）、終了の契約（監視スレッドの停止）には関わらないため、非同期にはしない。
- **トレイ**: 「設定(&S)...」のメニュー項目とダブルクリック、同時に1つだけ開く管理、保存の成功時の反映、終了時に画面を閉じる後片付け。
- **Program**: 変えない（トレイはエンジンが公開する入れ物を使う）。

## 8. 検証

### 自動テスト（Core、失敗するテストから書く）

- **保存**
  - 6項目だけが変わり、ほかのキーの値と順（未知のキー、数値の表記を含む）が保たれる
  - 6項目のキーが大文字小文字違いで書かれていたら、最初の位置に正式な表記で1回だけ書かれ、2回目以降の出現は消える
  - ファイルに無い6項目のキーは最後に §3 の順で足される
  - 録音の未設定は `""` で書かれる
  - BOM 付き UTF-8・LF・日本語をエスケープしない・末尾の改行1つ
  - 保存したファイルを `SettingsLoader.Load` で読むと、6項目が保存した値になり、ほかの項目は保存前に読んだ値と同じになる
  - ファイルが無い・解析できない・ルートがオブジェクトでないときは失敗を返し、ファイルを作らない・変えない
  - 置き換えに失敗したとき（読み取り専用の `config.json`、削除を共有しない開き方で別のプロセスが `config.json` を開いている）は失敗を返し、元のファイルは変わらず、一時ファイルが残らない
  - 一時ファイルを消せないとき（読み取り専用の `config.json.tmp` が残っていて、書くことも消すこともできない）は、理由の末尾に「一時ファイルが残っています: {パス}」が付く（plan 作成時に、この組み合わせで削除の失敗を起こせることを確かめて変更、2026-09-17）
  - **開いてから保存までの外部の編集**: 開いたときの内容から、6項目と6項目以外の両方を手で変えてから保存すると、6項目は画面の値、それ以外は保存直前のファイルの値になる。開いた後に削除・破損されたら、保存は失敗してファイルを作らない・変えない
- **開くときの読み込み**: ファイルが無い・解析できない・ルートがオブジェクトでないときに、保存できない状態と理由を返す。正常なファイルでは6項目が `SettingsLoader.Load` と同じ値になる
- **画面のモデル**
  - 一覧にある設定は、その名前が選ばれる（大文字小文字違いも一致として扱い、一覧の表記を選ぶ）
  - 一覧に無い設定は「（未接続）」付きの選択肢が先頭に足されて選ばれ、そのまま保存すると元の名前になる
  - 一覧に無い録音の設定では、並びが「（未接続）」付きの名前 →「（未設定）」→ 一覧のデバイスになり、「（未接続）」付きの名前が選ばれる
  - 同じ名前の重複は1つにまとまる
  - 録音は、「（未接続）」付きの名前が無ければ「（未設定）」が先頭にあり、空の設定ならそれが選ばれ、選ぶと空で保存される
  - 一覧を取得できなかった流れは、設定されている名前（と「（未設定）」）だけが選択肢になり、失敗理由が表示用に出る
  - 再生の項目が空になる選択結果は保存の値にならない
- **反映**
  - 入れ替えたあとの状態遷移では、新しい切り替え先と ON/OFF で切り替える（再生・録音、接続・切断のそれぞれ）
  - 入れ替えても、状態・既読の logId・ポーリング間隔などは変わらず、入れ替えだけでは切り替えない
  - **切り替えの途中の入れ替え**: 再生の切り替えの最中（`RecordingSwitcher.OnSwitch` の中）で入れ替えても、その回の録音は入れ替え前の切り替え先で行い、次の状態遷移から新しい設定を使う。Tick と起動時同期の両方で確かめる
  - 反映の値の組み立てで、6項目以外が元の値のまま残る
  - 既存のエンジンのテストは変えずに通る

フォーム、トレイの操作、デバイス一覧の取得（COM）には自動テストを作らない（最小版 spec §6 と同じく実機で確かめる）。

### 実機確認

最小版と同じく、端末を変える操作は作者が行い、作業環境は読み取りと記録を行う。日常利用中の新版を入れ替えるときは `docs/operations-minimal-csharp.md` の「4. 更新」に従う。

1. **開く**: メニューとダブルクリックで開くこと、2回目の操作で前面に出るだけで2つ開かないこと、開くまでに目立つ待ちが無いこと、初期値が `config.json` と一致すること
2. **未接続の表示**: Buds の USB ドングルを抜くなどで Buds の名前が一覧から消える状態を作れたら、「（未接続）」付きで選ばれていることを確かめる（作れなければ記録に残して省く）
3. **反映**: 接続時の再生先を別のデバイスに変えて保存し、その場で切り替わらないこと、再起動せずに次の Buds の出し入れで新しい切り替え先へ切り替わることを確かめる。ON/OFF を OFF にして保存し、その向きで切り替わらないことも確かめる。最後に元の設定へ戻す
4. **6項目すべての受け渡し**: 画面のコントロールと Core の値の取り違えを見つけるため、6項目をすべて保存前と違う値にして保存する（接続時・切断時の再生先、接続時・切断時の録音先、ON/OFF の2つ。録音の1つは「（未設定）」にする）。保存の前後で `config.json` を比べ、6項目がそれぞれ画面で選んだとおりのキーに入り、6項目以外の値と順が変わっていないことを確かめる。開き直して、画面の表示が保存した値と一致することも確かめる。続けて ON/OFF の2つを ON に戻して保存し（ON/OFF を変えた直後は、OFF の向きで切り替わらないため）、Buds の出し入れで、接続時・切断時それぞれ新しい再生先・録音先へ切り替わり、「（未設定）」にした向きの録音は変わらないことを確かめる。最後に元の設定へ戻す
5. **キャンセル**: 値を変えてから「キャンセル」と × のそれぞれで閉じ、`config.json` の更新日時と内容が変わらないこと、開き直すと元の値が表示されることを確かめる
6. **保存の失敗**: `config.json` を読み取り専用にして保存し、ダイアログが出て画面が閉じず、ファイルと動作中の設定が変わらないこと（次の出し入れで元の切り替え先へ切り替わる）を確かめる。最後に読み取り専用を外す
7. **開いた後の外部の編集**: 画面を開いたまま、メモ帳で `config.json` の6項目以外のキー（`logLevel` など）を変えて保存し、続けて設定画面で保存する。`config.json` の6項目以外がメモ帳で変えた値のまま残ることを確かめる。最後に元へ戻す
8. **一覧を取得できないとき**: 実機で列挙だけを失敗させる手段が無いため確認しない（記録に残す）。取得の失敗を画面へ渡す経路は Core のモデルのテストで確かめる
9. **終了**: 設定画面を開いたまま「終了」を選び、画面が閉じて従来どおり終了すること（終了コード0、ログの最終行）を確かめる

### 完了条件

- 設定画面から6項目を変えて保存でき、再起動せずに次の状態遷移から新しい設定で切り替わる
- 保存でデバイスがその場で切り替わらない
- 保存で `config.json` の6項目以外が変わらない。保存の失敗でファイルと動作中の設定が変わらない
- 既存の自動テストがすべて通り、切り替え・ログの文言・終了の挙動が変わっていない

## 9. 範囲外

- 6項目以外の設定（ポーリング間隔、`actionLogPath`、ログレベル、ログのサイズ上限、起動時同期）の画面での変更と、再起動なしの反映
- `config.json` の変更の見張りと、手で編集した内容の再起動なしの反映
- 保存時の衝突の検知（画面を開いた後にファイルが変わったかの確認）
- 保存した直後に、今の状態に合わせて切り替えること
- 未保存の変更がある状態で閉じるときの確認
- 画面を開いている間のデバイスの一覧の自動更新
- 起動時に設定画面を自動で開くこと、Windows 通知、多言語化、テーマへの追従
- 「既に既定」の判定を3ロールで見ること（Issue rurute/inzone-auto-switch#14）
- 旧版 PowerShell 版への設定画面の追加
