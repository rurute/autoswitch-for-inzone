# タスクバーに Buds のバッテリー残量を出す（Issue rurute/inzone-auto-switch#27）

## 目的

INZONE Buds を使っている最中に、**あとどれくらい持つかをちらっと見たい**（作者の言葉）。そのために、Windows 11 のタスクバーに、ヘッドホンの絵と残量の「％」を常に出す。設定で ON/OFF できるようにする。

前の設計（`2026-11-25-dongle-detection-design.md`）では、残量の表示を「battery-hub で見ている」として非ゴールにしていた。作者はその後 battery-hub をアンインストールしたので、残量を見る手段がいまはない。

残量のデータは、すでに手元にある。接続・切断を判定するために、ドングルへ 2〜5 秒おきに問い合わせており、その返答（`BudsLevels`）に左・右・ケースの残量が入っている。いまは接続中かどうかの判定にしか使っていない。**新しい通信は要らず、表示を作るだけでよい。**

## ゴール / 非ゴール / アンチゴール

- ゴール: 設定で ON にすると、Buds の接続中、メインのモニターのタスクバーに、ヘッドホンの絵と残量（例 `78%`）が出る。
- ゴール: 残量が 20% 以下になると、数字の色が変わり、数字を読まなくても「そろそろ」と分かる。
- ゴール: 設定画面のチェックボックスで ON/OFF でき、保存するとアプリを再起動せずに反映する。
- 非ゴール: ケースの残量、左右を分けた表示。
- 非ゴール: 残量が少ないときの通知や音。段階を 2 つ以上にした色分け。しきい値の設定。
- 非ゴール: トレイアイコンへの数字の表示。トレイアイコンは今のまま。
- 非ゴール: 表示位置の調整、サブモニターのタスクバーへの表示、タスクバーを上・左・右に置いた場合への対応（Windows 11 の標準では下だけ）。
- 非ゴール: 旧 PowerShell 版。
- アンチゴール: **トレイ（通知領域）に出すこと。** 作者は「トレイではなくバーに」と明示した。
- アンチゴール: タスクバーのアプリのアイコンや時計に重なって、タスクバーが使いにくくなること。
- アンチゴール: 全画面のゲームや動画の上に表示が残ること。
- アンチゴール: 表示がクリックやフォーカスを奪うこと（表示をクリックしても、その下のタスクバーの操作を邪魔しない）。
- アンチゴール: 表示の失敗（タスクバーが見つからない、描けない）で、監視と切り替えが止まること。

## 制約

- Windows 11 には、アプリがタスクバーに部品を足す公式の仕組みがない（Windows 10 までのツールバー、いわゆる deskband は Windows 11 で使えない）。
- トレイアイコンは 16×16 ピクセルほどしかなく、ヘッドホンの絵と「100%」を並べると読めない（トレイを避ける理由の 1 つでもある）。
- 作者の環境は日本語版 Windows 11、タスクバーは下、アイコンは中央寄せ（標準のまま）。

## 検討した案

HUMAN が選んだ: **案 A**。

- **A. タスクバーの上に小さな窓を重ねる（採用）**。TrafficMonitor などの常駐ツールと同じやり方で、タスクバーの位置を調べ、その上に枠のない小さな窓を置く。ヘッドホンの絵と `78%` を並べて出せる。ご希望にいちばん近い。公式の仕組みではないので、置く場所を自分で計算する。アイコンの数・複数モニター・表示倍率・全画面・自動非表示・Windows の更新で、ずれたり隠れたりしうる。作る量が最も多い。そこで、最初は範囲を絞る（下の「設計」）。
- B. タスクバーにアプリのボタンを 1 つ出し、そのアイコンに数字を描く: 公式の仕組みで壊れにくいが、絵は 24 ピクセルほどで、ヘッドホンと「%」は入らない。Alt+Tab にも出る。ご希望の見え方を満たせないので外した。
- （外した）トレイアイコンに数字を描く: アンチゴール。

## 設計

### 見え方

```
┌──────────────────────────────────────────────────────────────┐
│ ⊞ 🔍   [アプリのアイコン…]          🎧 78%  ^ 🔊 📶  12:34   │
└──────────────────────────────────────────────────────────────┘
                                      ↑ここに重ねる
```

- 置き場所: メインのモニターのタスクバーの、**トレイ（通知領域）のすぐ左**（Claude の判断）。Windows 11 の標準では、左端にウィジェット（天気）、中央にアプリのアイコンがあり、トレイの左は空いていることが多い。時計の近くで目にも入りやすい。
- 中身: ヘッドホンの絵（トレイアイコンと同じ形でよい）と、残量の数字と `%`。絵の色は文字と同じ（下の「文字の色」）。高さはタスクバーに合わせ、上下の中央に置く。
- 文字と絵の色: タスクバーがダークなら白、ライトなら黒（Windows の「既定のアプリモード」ではなく「Windows モード」の色。`HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize` の `SystemUsesLightTheme`）。テーマが変わったら追従する。
- 背景: 透明（タスクバーの色が透けて見える）。

### 出す値

- 出すのは**左右のうち低いほう**の残量（先に切れるほうの耳が持ち時間を決めるため）。
- 片耳だけ報告がある（片耳をケースに戻した）ときは、その耳の残量。
- ケースの残量は使わない。

### 残量が少ないとき

- **20% 以下**で、数字と `%` をオレンジにする。ヘッドホンの絵は白（ライトなら黒）のまま。
- 段階は 1 つだけ。しきい値は 20 に固定（設定項目にしない。使ってみて変えたくなったら足す）。
- 色はライトとダークで濃さを分け、どちらのタスクバーでも読めるものにする。目安（Claude の判断。実機で見て調整してよい）: ダークのタスクバーでは `#FF9F43`、ライトでは `#C2410C`。

```
ふだん:     🎧 78%    （白。ライトのタスクバーでは黒）
20% 以下:   🎧 18%    （数字がオレンジ）
```

### いつ出すか

出すのは、次のすべてを満たすときだけ。どれかが崩れたら隠す（窓を消す）。

1. 設定が ON。
2. 状態が接続中で、最後の問い合わせの返答に左右どちらかの残量がある（切断中・不明・ドングルが読めないときは出さない）。
3. メインのモニターのタスクバーと、そのトレイの位置が分かる。
4. トレイの左に、表示が入る空きがある（アプリのアイコンと重ならない）。
5. タスクバーが画面に出ている（自動非表示で隠れていない）。
6. メインのモニターで、全画面のアプリが前に出ていない。

- 3 と 4 が理由で出せないときは、ログに Warn を **1 回だけ**書く（出せるようになったら Info を 1 回）。毎回の判定で同じ行を書き続けない。5 と 6 は普通の操作なので、ログに書かない（Debug ならよい）。
- 4 の判定は、**UI Automation でタスクバーのアプリのボタンの位置を実際に調べて行う**（HUMAN が選んだ。2026-11-26。builder check の指摘 1）。ボタンの数と幅から見積もるやり方は使わない（外れると重なるため）。
  - UI Automation で位置を取れない（Windows の更新で構造が変わった、など）ときは、条件 4 を満たさないものとして表示を消し、3・4 と同じく Warn を 1 回だけ書く。重ねて出すことはしない。
  - 呼び出すスレッドや間隔、失敗の扱いの細部は builder に任せる。ただし UI スレッドを止めないこと、監視と切り替えを止めないこと。
  - 試作でこの方法が使えないと分かったら、HUMAN へ戻る（下の「作る順番」）。

### 更新の頻度と位置の追従

- 残量: 問い合わせのたびに届く値で書き換える。同じ値なら描き直さなくてよい。
- 位置: タスクバーの位置や大きさ、トレイの幅（アイコンの増減で変わる）、表示倍率、画面の解像度が変わったら置き直す。変化の知らせを受けて置き直すか、一定の間隔で確かめるかは builder に任せる（間隔で確かめるなら 1〜2 秒程度）。
- Explorer が再起動してタスクバーが作り直されたら（`TaskbarCreated` のメッセージ）、置き直す。

### 窓のふるまい

- 枠なし、タスクバー・Alt+Tab に出ない、アクティブにならない、クリックは下のタスクバーへ素通しする。
- タスクバーより手前に見えること。タスクバーをクリックしたときなどに一瞬裏に隠れるのはよいが（作者が許容した。下の「試作の結果」）、0.3 秒程度で手前に戻り、裏に隠れたままにならない。
- 重ね方は、試作の結果から最前面の窓に決めた（下の「試作の結果」）。

### 監視スレッドから表示への値の渡し方

- 今の `AutoSwitchEngine` は、状態（`StateChanged`）と問い合わせの結果の種類（`QueryCompleted`）しか外に出していない。残量（`BudsLevels`）も、問い合わせのたびに外へ渡せるようにする。形は builder に任せる。
- 表示は UI スレッドで行う。今のトレイアイコンと同じく、隠し Control の `BeginInvoke` で UI スレッドへ渡す。
- 表示の側で例外が起きても、監視スレッドへ投げ返さない（今の `StateChanged` と同じ扱い）。

### 設定

- `config.json` に `showTaskbarBattery`（真偽）を足す。既定は **`false`**（新しい版を入れただけで見た目が変わらないようにする。Claude の判断）。
- 設定画面にチェックボックス「タスクバーに残量を表示する」を足す。今の 6 項目と同じく、保存したら再起動せずに反映する（ON にした瞬間に、接続中なら出る。OFF にした瞬間に消える）。
- 今の `SwitchSettings` は「切り替えの 6 項目」という名前と説明になっている。7 項目目を足すか、別の入れ物にするかは builder に任せる。どちらでも、保存は「読み直して該当キーだけ書き換える」今の `SettingsFileEditor` のやり方に合わせ、保存のログにもこの項目を出す。
- 手で `config.json` を編集した場合は、今のほかの項目と同じく起動時にだけ読む。

### 作る順番

重ね方と空きの判定は、実機でしか確かめられない。そこで、**最初の Task で、使い捨てでよいので実機で確かめる**（作者に実機で見てもらう）。確かめる点:

- 選んだ重ね方で、表示がトレイの左に出て、タスクバーをクリックしたあとも手前に見え続けるか。
- トレイの位置と、アプリのアイコンの右端を UI Automation で取れるか（空きの判定）。アプリをたくさん開いてアイコンがトレイの近くまで並んだとき、表示が消えるか。
- 全画面のアプリで隠れるか。

試作は使い捨てで、本実装の計画（plan）には入れない（Claude の判断。builder check の指摘 2）。重ね方は試作の結果しだいで後の Task が大きく変わるため、試作 → 作者が実機で合否を見る → その結果をこの設計書に書き足す → 本実装の計画を書く、の順にする。3 点のうち 1 つでも駄目、または「一瞬だけ裏に隠れる」のように怪しい点があれば、その結果を持って HUMAN に戻り、進めるかどうかを HUMAN が決める（Claude の判断。builder check の指摘 3）。

### 試作の結果（2026-11-26、作者の環境）

作者の環境: Windows 11（`10.0.26300`、26H2）、モニター 1 枚（3440×1440、表示倍率 100%）、タスクバーは下・中央寄せ、ダーク。

試作の作り: 最前面の窓（`WS_EX_TOPMOST`、レイヤード窓に `UpdateLayeredWindow` で透過描画、`WS_EX_TRANSPARENT` `WS_EX_TOOLWINDOW` `WS_EX_NOACTIVATE`）。0.3 秒ごとに位置を計算し、`SetWindowPos(HWND_TOPMOST)` で手前へ置き直す。位置の取得は別スレッド（MTA）で 1 秒ごと。

| 確かめた点 | 結果 |
|---|---|
| トレイの位置 | `Shell_TrayWnd` の子 `TrayNotifyWnd` の左端と、UI Automation の `SystemTray.*` の左端が一致した。トレイのアイコンが増減すると追従した |
| アプリのボタンの位置 | UI Automation で `Shell_TrayWnd` の子孫から ClassName `Taskbar.TaskListButtonAutomationPeer` の要素（13 個）が取れ、右端が分かった。取得は 300ms 未満 |
| 手前に見え続けるか | タスクバーをクリックしたときと、全画面から戻ったときに、タスクバーが表示より手前になった（記録 2 回）。0.3 秒以内に手前へ戻した。作者の判定: 「一瞬消えたが気になるほどではない」→ 合格 |
| クリックの素通し・見た目 | 問題なし（作者） |
| 全画面 | 前面の窓がモニター全体を覆うときに隠し、やめると戻った |
| ライト／ダークの色、20% 以下のオレンジ | ダークで白とオレンジ（`#FF9F43`）が読めることを画面写真で確かめた。ライトは未確認 |
| アイコンが迫ったときに消えるか | **未確認**（アプリのアイコンがトレイの近くまで並ばなかった）。作者が「進む」と判断した（2026-11-26）。自動テストと実機での確認 13 で確かめる |

この結果から、本実装は次のとおりにする:

- 重ね方は**最前面の窓**（タスクバーの子として埋め込む方法は試していない。使わない）。タスクバーより手前に戻す見張りを 0.3 秒程度の間隔で行う（「窓のふるまい」の「裏に隠れたままにならない」をこれで満たす。一瞬隠れるのは作者が許容した）。
- トレイの左端は `TrayNotifyWnd` から取る。アプリのボタンの右端は、UI Automation の ClassName `Taskbar.TaskListButtonAutomationPeer` の要素から取る。1 つも見つからないときは「位置を取れない」として隠す。
- UI Automation の呼び出しは UI スレッドの外で行う。

## テスト

自動テスト（Core と、App の描画・計算の部分）:

- 出す値: 左右とも残量あり → 低いほう、片方だけ → その値、両方なし → 出さない、ケースの値は使わない。
- 少ない判定: 21 → ふだんの色、20 → オレンジ、0 → オレンジ。
- 置き場所の計算を純粋な関数にする（タスクバーの矩形・トレイの矩形・アプリのアイコンの右端・表示の大きさ → 置く矩形、または「空きなし」）。空きが足りる・ちょうど・足りない、を確かめる。
- 「いつ出すか」の 6 条件の組み合わせ（純粋な関数にできる部分）。
- UI Automation で位置を取れないとき: 位置を取る部分を偽物に差し替え、取れない → 表示が消え Warn が 1 回だけ出る、取れるようになる → 出て Info が 1 回出る、を確かめる（実機では取れない状態を作れないため）。
- 設定: `showTaskbarBattery` がないときは `false`、真偽でないときは警告して `false`。保存でこのキーだけが書き換わり、ほかのキーは残る。設定画面のモデルが値を往復させる。
- 描画: 今の `TrayIcons.Render` のテストと同じように、ビットマップに描いた結果のピクセルで、ふだんとオレンジの色の違いを確かめる程度。

自動テストで扱わないもの（実機で確かめる）: タスクバーやトレイの位置の取得、窓の重なり、テーマや表示倍率の追従、全画面の判定、Explorer の再起動。

## 実機での確認（実装のあと、インストールして）

1. 設定画面で ON にして保存すると、Buds の接続中、トレイのすぐ左に `🎧 nn%` が出る。OFF にすると消える。どちらも再起動は要らない。
2. 出る数字が、左右のうち低いほうの残量と合う（INZONE Hub を手で起動し、Hub に出る左右の残量と比べる）。
3. 残量が 20% 以下のとき、数字がオレンジになる（残量が下がるのを待つか、確認用に値を差し替えたビルドで確かめる）。
4. ふたを閉じると消え、取り出すと出る。
5. タスクバーをクリックしたり、アプリを切り替えたりしても、表示が裏に隠れたままにならない（一瞬消えてすぐ戻るのはよい）。表示をクリックしても何も起きず、フォーカスも奪わない。
6. トレイのアイコンが増減しても（例: 別のアプリを起動してトレイにアイコンを出す）、トレイの左に付いていく。
7. ライト／ダークのテーマを切り替えると、文字の色が追従する。
8. 表示倍率を 100% と 150% で切り替えても、位置と大きさが合う。
9. 全画面のゲームや動画で、表示が上に残らない。
10. タスクバーの自動非表示を ON にすると、タスクバーが隠れている間は表示も隠れる。
11. Explorer を再起動（タスク マネージャーから）すると、置き直されて出る。
12. 設定が OFF のとき、起動しても何も出ない（初期状態）。
13. アプリをたくさん開いて、タスクバーのアイコンがトレイの近くまで並ぶと、表示が消える（アイコンに重ならない）。ログに Warn が 1 回だけ出る。アプリを閉じて空きができると、また出て、ログに Info が 1 回出る。
